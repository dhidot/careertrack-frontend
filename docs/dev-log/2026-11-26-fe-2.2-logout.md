## Alur logout

```
Browser                  BFF (Next.js)                       Gateway → Auth
───────                  ─────────────                       ──────────────
klik "Sign out"
POST /api/v1/auth/logout ─▶ 1. cek Origin
  (cookie ikut otomatis)    2. baca cookie HttpOnly
                            3. POST /api/auth/logout ─────────▶ Bearer <access>
                               body {refreshToken}              revoke refresh token
                            4. hapus 2 cookie (Max-Age=0)
                       ◀─── 200 {sessionRevoked: true}
window.location.replace("/login")
```

**Kenapa harus lewat BFF?** Token disimpan di cookie HttpOnly supaya tidak bisa dibaca JavaScript (perlindungan dari XSS). Konsekuensinya, browser juga tidak bisa menghapusnya sendiri. Hanya server yang bisa, dengan `Set-Cookie ... Max-Age=0`. Atribut `path`, `httpOnly`, `sameSite`, dan `secure` harus sama dengan saat cookie dibuat. Kalau beda, browser menganggapnya cookie lain.

## Kontrak Auth Service (dicek dari source `auth-service`)

| Endpoint | Butuh | Efek |
|---|---|---|
| `POST /api/auth/logout` | `Authorization: Bearer <access>` + body `{refreshToken}` | Revoke satu refresh token. Auth mengecek token itu milik user yang login. |
| `POST /api/auth/logout-all` | `Authorization: Bearer <access>` | Naikkan `token_version` user dan revoke semua refresh token |

## Keputusan desain

### 1. Rotasi sekali lalu coba ulang saat access token kadaluarsa
Access token cuma berlaku 15 menit. Kalau user logout setelah tab ditinggal lama, Auth membalas 401. Kalau BFF hanya menghapus cookie, refresh token di database tetap aktif sampai 7 hari.

Solusinya, saat dapat 401, BFF memanggil `/api/auth/refresh` (Auth me-revoke token lama dan memberi pasangan baru), lalu memanggil logout lagi dengan pasangan baru. Hasilnya kedua token berakhir revoked. Percobaan ulang hanya sekali, jadi tidak ada loop.

### 2. `logout` fail-open, `logout-all` fail-closed

| | `logout` | `logout-all` |
|---|---|---|
| Kalau Auth mati | Cookie **tetap dihapus**, balas 200 dengan `sessionRevoked: false` | Cookie **tidak dihapus**, balas 502/503/504, muncul pesan error |
| Alasan | Keluar dari browser ini selalu bisa dipenuhi. Gagal-gagalan hanya membuat user terjebak dalam keadaan login. | User ingin semua device keluar, misalnya karena HP hilang. Kalau hanya browser ini yang keluar, user mengira HP-nya aman padahal belum. |

### 3. Simpan token hasil rotasi kalau `logout-all` gagal
Kalau token sudah dirotasi lalu `logout-all` gagal, refresh token lama di browser sudah di-revoke. Respons error karena itu membawa pasangan token baru (`setSessionCookies`), supaya user tidak ter-logout diam-diam.

### 4. Proteksi CSRF
Kedua route menolak request yang `Origin`-nya bukan origin aplikasi, termasuk request tanpa `Origin`. Tanpa cek ini, situs lain bisa membuat form yang POST ke `/api/v1/auth/logout-all` dengan cookie user.

### 5. Client
- `signOut` mengosongkan cache single-flight `/me` supaya respons `/me` yang terlambat tidak membuat tab ini kembali login.
- Network error dilaporkan sebagai `unavailable`, termasuk untuk logout biasa. Request yang tidak sampai berarti BFF tidak jalan dan cookie masih ada.
- Navigasi pakai `window.location.replace` (full reload). Semua state React terbuang, `ServerSessionGuard` memeriksa cookie yang sudah kosong, dan halaman dashboard tidak muncul lagi saat tombol Back ditekan.
- Selama proses, kedua tombol di-disable dan menu diberi `aria-busy`. Error tampil dengan `role="alert"`. Panah atas/bawah berpindah antar item (pola menu WAI-ARIA).

## Batasan yang masih ada

1. Logout biasa hanya me-revoke refresh token. Access token yang sempat dicuri masih valid sampai maksimal 15 menit. `logout-all` tidak punya masalah ini karena kenaikan `token_version` langsung membatalkan semua JWT.
2. Tab lain baru ter-logout saat request berikutnya. Bisa disinkronkan dengan `BroadcastChannel` nanti.
3. Rate limit gateway masih memakai kunci per path (satu jatah bersama semua user). Rotasi saat logout ikut memakai jatah `/api/auth/refresh`.
4. Next.js 16.4.0 dilaporkan terkena kerentanan keamanan saat build. Perlu upgrade (`next upgrade --agent=security`).

## Cara mencoba manual

1. Jalankan Auth Service, API Gateway, lalu `pnpm dev` di `apps/web` dengan `API_GATEWAY_URL=http://127.0.0.1:8080`.
2. Login, buka profile menu (kanan atas), klik **Sign out**. Hasil yang diharapkan: diarahkan ke `/login`, cookie `careertrack_*` hilang di DevTools, dan membuka `/dashboard` lagi mengarah ke login.
3. Login di dua browser, lalu klik **Sign out of all devices** di salah satunya. Browser kedua harus diminta login lagi saat request berikutnya.
